# AI Daily Coach — implementation notes

> Stage 1 only. This branch is **not deployed**. Stage 2 (Edge Function) and Stage 3 (weekly optimisation / Owner summary) remain to be implemented and reviewed.

## Scope and invariants

- Scope: `supabase/migrations/*ai_coach*.sql`, `supabase/functions/agent-coach/`, `tests/ai-coach/`, and this file.
- Existing mandatory courses, MCQs, certification, statuses, payout, tiering, profit-guard, `get_or_create_daily_mission_internal`, and `agent_today_progress_internal` remain untouched.
- Data stays in the `private` schema with RLS enabled, no client policies, and no `anon` / `authenticated` grants. Internal functions use `SECURITY DEFINER SET search_path = ''` and grant `EXECUTE` only to `service_role`. Two public-schema RPC gateways (`public.coach_build_plan_internal` and `public.coach_complete_task_internal`) forward to private functions, are service-role-only, and do not expose any private table.
- Agent-facing code must authenticate with `auth.getUser()` and pass only the verified agent id; never accept arbitrary `agent_id` from the request body.
- A task's `ordered` outcome is an Agent self-report, **not proof of purchase** and **never** creates an order or commission.

## Stage 1 — deterministic pipeline

The new migration is `20261114190000_ai_coach_stage1.sql`.

1. `private.coach_build_plan_internal(agent_id, date)` validates existence, skips `is_demo=true`, holds a transaction advisory lock per agent/day, and reads existing `daily_missions` and `agent_today_progress_internal` without calling the mutating get-or-create function.
2. For non-locked agents it prioritises eligible leads in this order: awaiting a decision on an approved/sent/accepted quote; due follow-up; qualified but not yet quoted; recent completed purchaser (referral); past contact inactive for 30 days (re-engagement). Every lead id may appear at most once per date, enforced by a unique index.
3. Fill remaining capacity with demand discovery, an educational content prompt, or brief conversation practice. A `trainee`, `restricted`, `recovery`, `dormant`, or `suspended` Agent gets **only** discovery, content, and practice; no customer lead id is attached.
4. A previous seven-day task completion ratio of at least 80% produces five tasks; 50–79.9% produces four; otherwise three. A new agent starts with three. The Stage 1 SQL suite checks the three-, four-, and five-task paths.
5. Date calculation uses `Asia/Kuching`. The upcoming 14-day window recognises a limited set of reliably computable occasions; it does not guess Qixi, Eid, or other changing lunar dates.
6. Each task includes English / Chinese titles, a short sales rationale, a safe deterministic draft, estimated minutes, and priority. No price, inventory guarantee, or fixed delivery promise is generated by Stage 1.
7. `private.coach_complete_task_internal(agent_id, task_id, outcome, note)` checks task ownership, writes a single outcome, and updates only private skill evidence. Repeating `done` does not increase skill levels twice. These levels are *coach-only* and unrelated to Agent tiers or certification.
8. `private.coach_review_day_internal(agent_id,date)` stores task completion and self-reported funnel outcome counts in the plan summary. It does not change business records.

### Isolated regression checks

Run `psql -v ON_ERROR_STOP=1 -f tests/ai-coach/stage1.sql` **only on a throwaway/staging database after applying the migration**. This test uses synthetic Agent fixtures inside a `BEGIN ... ROLLBACK` transaction and checks:

- A/B Agent separation (including cross-Agent task completion),
- demo Agent exclusion,
- repeat generation and repeat completion idempotency,
- 3 versus 5 task count from prior-week completion,
- selling-locked Agent task restrictions,
- evidence and review writes,
- RLS and denied client grants.

No production seed agents are created by this branch. Production migration has **not** been applied. Stage 1 SQL tests require a database and have not been run on production.

## 给老板看的说明（阶段 1）

这套引擎的第一步，是每天自动从现有客户记录找出最接近成交的动作，再给 Agent 三至五件当天可以执行的事。任务会解释「为什么值得做」，并提供中英文基础说法。做完后记录客户反应，晚上统计当天完成情况，用于接下来调整安排。新手或受限 Agent 不会收到需要销售权限的客户跟进任务。整个阶段不改变佣金、等级、解锁、报价审核或利润底线。目前仅完成数据库规则与测试脚本；AI 个性化话术、陪练、自动后续跟进、每周策略优化以及 Owner 摘要，将在阶段 2／3 实作并由 Claude 审查后才可考虑部署。
